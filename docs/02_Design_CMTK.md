## 2. Typography

```yaml
fontFamily: "Kanit, system-ui, -apple-system, sans-serif"
```

Kanit เป็น geometric sans ที่มีชุดตัวอักษรไทยครบ ตัวเลขเป็น tabular ได้
และเว็บบริษัทใช้อยู่แล้ว — ไม่ต้องขออนุมัติฟอนต์ใหม่

| Token | ขนาด | น้ำหนัก | ใช้กับ |
|---|---|---|---|
| `page-title` | 24px | 600 | ชื่อหน้า (ชื่อมอเตอร์, สรุปรายเดือน) |
| `metric-hero` | 32px | 600 | ตัวเลขเมตริกในการ์ดคะแนน |
| `metric` | 20px | 600 | ค่าเซ็นเซอร์บนการ์ดมอเตอร์ |
| `section` | 16px | 600 | หัวข้อการ์ด |
| `body` | 14px | 400 | เนื้อความทั่วไป |
| `body-strong` | 14px | 500 | ชื่อรายการในตาราง |
| `caption` | 12px | 400 | หน่วย ป้ายกำกับ คำอธิบายใต้ภาพ |

**กฎที่ต้องบังคับ**
- ตัวเลขทุกตัวที่ต้องเทียบกันในแนวตั้งใช้ `tabular-nums` — ไม่งั้นหลักเลื่อนแล้วอ่านผิด
- หน่วย (mm/s, °C) แยกเป็น `caption` สีอ่อนกว่าเสมอ ไม่รวมกับตัวเลข
- ห้ามใช้ตัวพิมพ์ใหญ่ทั้งหมดกับข้อความไทย

```yaml
spacing:

  xs:  8px
  sm:  12px
```

**ต่างจาก Style_Apple ตรงนี้มากที่สุด** — SOP อ้างอิงใช้ `section: 80px`

```yaml
button-primary:
  background: "{colors.primary}"
  text: "{colors.on-primary}"
  rounded: "{rounded.md}"
  padding: 10px 16px
  minHeight: 44px

button-ghost:
  background: transparent
  text: "{colors.primary}"
  border: "1px solid {colors.hairline}"
  rounded: "{rounded.md}"
  minHeight: 44px

input:
  border: "1px solid {colors.hairline}"
  rounded: "{rounded.sm}"
  padding: 10px 12px
  minHeight: 44px

card:
  background: "{colors.surface}"
  border: "1px solid {colors.hairline}"
  rounded: "{rounded.lg}"
  padding: 16px
  shadow: none

card-alert:
  border: "2px solid {colors.warning | colors.alarm}"   # ตามระดับที่เกิด

toast:
  background: "{colors.surface}"
  rounded: "{rounded.lg}"
  shadow: "0 6px 24px rgba(16,32,56,.14)"
  autoDismiss: 5000ms

save-bar:
  position: sticky-bottom
  border: "1px solid {colors.primary}"
  shadow: "0 6px 24px rgba(16,32,56,.14)"
  แสดงเมื่อ: มีค่าที่แก้แล้วยังไม่บันทึก
```

### Component เฉพาะของงานนี้

**`zone-band`** — แถบ 4 ช่อง A│B│C│D ช่องที่ active เติมสีและแสดงตัวอักษร
ให้ข้อมูลสองชั้น: อยู่โซนไหน และเหลือระยะห่างจากโซน D เท่าไหร่
ตัวเลข `1.41 mm/s` เดี่ยว ๆ บอกไม่ได้ว่าดีหรือแย่ แต่ "B จาก 4 โซน" บอกได้ทันที
ขนาด `sm` (20px) บนการ์ด · `lg` (36px) บนหน้ารายละเอียด

**`port-rail`** — แถบ 8 ช่องจำลองตัว IO-Link Master จริง
ช่องว่างแสดงเป็นเส้นประคำว่า "ว่าง" เพราะนั่นคือข้อมูล (ขยายได้อีก 4 มอเตอร์)
ช่างที่ยืนหน้าตู้แปลเป็นของจริงได้โดยไม่ต้องตีความ

**`mount-3d`** — โมเดลมอเตอร์เลือกจุดติดตั้งเซ็นเซอร์ (ISO 20816: DE-H/V/A, NDE-H/V)
ลากหมุนได้ · ลากจุดที่เลือกเพื่อปรับตำแหน่ง · จุดเกาะติดผิวมอเตอร์เสมอ
**ต้องมี dropdown คู่กันเสมอ** — WebGL canvas กด Tab เข้าไม่ได้ ถ้ามีแต่ 3D จะตก Gate

## 6. Accessibility (NFR-09, NFR-10)

**สีห้ามเป็นสัญญาณเดียว — บังคับทุกจุด**

| สถานะ | สี | ตัวช่วยที่ไม่ใช่สี |
|---|---|---|
| ISO zone | เขียว/มะนาว/ส้ม/แดง | **ตัวอักษร A B C D** |
| ประเภท event | ตามระดับ | **สัญลักษณ์ ▲ ◆ ● ■** + ข้อความ |
| เซ็นเซอร์หลุด | เทา | ไอคอน + ข้อความ "ไม่มีข้อมูลเข้ามา" |
| เส้นในกราฟ | สีต่อมอเตอร์ | **เส้นทึบ = ค่าจริง · เส้นประ = ค่าทำนาย** |

**คีย์บอร์ด**
- Tab เข้าถึงทุกจุดที่คลิกได้ รวมวันในปฏิทินและ legend ของกราฟ
- วันที่ไม่มีเหตุการณ์ตั้ง `disabled` — ไม่ดูด focus ไปเปล่า ๆ
- `focus-visible` ring ทุกจุด ไม่ตัด outline ทิ้ง
- โมเดล 3D มี dropdown คู่ขนานทำงานแทนได้ทั้งหมด

**สถานะ async — ทุกหน้าที่ดึงข้อมูลต้องมีครบ 4**
`loading` · `empty` · `error` + ปุ่มลองใหม่ · `stale` (มีข้อมูลแต่เก่าเกินกำหนด)
ต้นแบบมีปุ่มสลับสถานะไว้ใต้กราฟเพื่อให้รีวิวได้โดยไม่ต้องรอให้เกิดจริง

**Live region** — toast ใช้ `role="status"` + `aria-live="polite"`

## 7. เนื้อหาและถ้อยคำ

กฎที่มาจากงานนี้โดยเฉพาะ ไม่ใช่กฎ UI ทั่วไป

- **อย่าทำให้ระบบดูฉลาดกว่าที่เป็น** — เส้นทำนายติดป้าย "สถิติ · ยังไม่ใช่ ML" ในหน้าจอ
  ถ้าไม่เขียน คนใช้จะเชื่อตัวเลขมากเกินไป
- **บอกเมื่อไม่รู้** — เซ็นเซอร์หลุดต้องขึ้น "ไม่มีข้อมูลเข้ามา" ห้ามโชว์ค่าเก่าค้าง
  เงียบไม่ได้แปลว่าปลอดภัย (AC-011-04)
- **อธิบายเหตุผลตรงที่ต้องกรอก** — ช่อง cause code มีคอลัมน์ข้าง ๆ อธิบายว่าข้อมูลนี้ไปไหน
  ไม่งั้นคนจะเลือก `other` ทุกครั้ง
- **ข้อความ error ห้ามรั่วข้อมูล** — หน้า login ไม่บอกว่า email มีอยู่จริงหรือไม่ (AC-001-02)
- **ป้ายต้องแยกแนวคิดที่ต่างกัน** — "เกณฑ์ตัดสิน" (ใช้ให้คะแนนการทำนาย) ต่างจาก
  "Warning/Alarm" (ระดับเตือนจริง) แม้เป็นตัวเลขเดียวกัน

## 8. Do / Don't

### Do
- ใช้น้ำเงิน GS เป็นสีโต้ตอบเพียงสีเดียว
- สงวนสีสถานะไว้บอกสถานะเครื่องจักรเท่านั้น
- ใส่ตัวอักษรหรือสัญลักษณ์คู่กับสีเสมอ
- แสดงหน่วยแยกจากตัวเลข ด้วยสีอ่อนกว่า
- ให้ตัวเลขที่เทียบกันใช้ `tabular-nums`
- ปิด animation ของกราฟที่สลับไปมาบ่อย

### Don't
- ห้ามใช้เขียว/ส้ม/แดง กับปุ่มหรือของตกแต่ง — จะไปชนกับความหมายสถานะ
- ห้ามใส่เงาใต้การ์ด — เงาสงวนไว้ให้ของที่ลอยจริง (toast, popup, save bar)
- ห้ามทำ hero หรือเว้นช่วงใหญ่ — เสียพื้นที่ที่ควรแสดงข้อมูล
- ห้ามใช้ WebGL เป็นทางเดียวในการทำอะไรสักอย่าง
- ห้ามเฉลี่ยค่าข้ามมอเตอร์ในกราฟเดียว — สเกลต่างกัน ได้ตัวเลขที่ไม่มีความหมายกับเครื่องไหนเลย
- ห้ามใช้จุลภาคเป็นตัวคั่นที่ใดก็ตาม — ชื่อ field จาก MQTT มีจุลภาคอยู่ข้างใน (NFR-16)

## 10. ยังไม่ได้ทำ (ตั้งใจ)

|---|---|
| Dark mode | ไม่มีใน requirement · ห้องควบคุมเปิดไฟตลอด |
